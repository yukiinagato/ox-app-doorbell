# 待命媒体与首帧验收

室内 Core 为直接连接的门口机保持最多四条已认证媒体连接。每台门口机最多接受八个待命所有者，且这些连接计入 HTTP 媒体连接总限额。控制消息使用已有的认证 mesh 通道，视频数据通过独立的、固定证书指纹的 HTTPS 响应传输。

`GET /media-standby.mp4` 要求有效的节点 MAC，以及 `X-Doorbell-Channel` 中的 32 字符通道标识。响应类型为 `application/x-doorbell-standby-v1`。空闲时每秒发送一个 12 字节 `dbrt` 盒：标准 MP4 盒头后跟大端旋转角度。此时没有 VideoTrack 订阅，不需要 H.264 编码或接收端解码。启动时以有时限的本地订阅预热一次编码器。每次格式变化后，仅通过空闲通道发送一次缓存格式信息，kiosk 因而可以提前创建并保留解码器，无须解码视频。运行遥测会去重并合并突发更新；呼叫事件与激活命令仍立即发送。

mesh 命令 `standby_video_v1` 将激活代次绑定到请求节点及通道。代次零表示停止。活动代次每五秒续期，十五秒未续期即过期。激活时发送 24 字节 `dbeg` 盒，包含大端代次和源设备系统时间毫秒值，然后发送初始化数据和 fMP4 片段。订阅请求新的 IDR，拒绝激活前的缓存 IDR。接收端过滤旧代次。每个订阅最多缓存 4 MiB、128 个盒；超限时结束订阅，不破坏帧依赖。

呼叫提示在通知 UI 前预留订阅；预留在五秒后或呼叫不再响铃时过期。第二个并发观看者使用原有媒体路径。成员移除、密钥变化、地址或证书指纹变化、心跳超时及关闭应用都会使对应通道失效。旧版门口机保留原有 HTTPS 回退，失败连接的重试间隔至少十五秒。

`media-startup` 日志分别记录 DNS、TCP、TLS、请求发送、响应头、首批响应数据及待命激活耗时。kiosk 记录呼叫接纳、请求、解码器配置、IDR 接收、UIKit 提交及首帧采集时间。`press_local_wall_ms` 将校正后的按铃事件时间换算为接收端原始系统时间；`capture_cutoff_ms` 与摄像头采集时间都使用源设备原始时间。禁止混用校正时间和原始时间。 媒体日志使用有上限的异步写入队列；计时应使用日志内的事件时间戳，而非日志实际送达时间。

通过认证的本机 UI 请求可直接领取 Core 已预留的订阅，无须再经过一次状态循环；其他请求仍执行正常媒体权限检查。
