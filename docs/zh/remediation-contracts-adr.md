## C01：权威职责与兼容性

Core 负责授权、通话状态、过期处理和配置验证。
保留 `db_platform_v2` 的大小/版本协商机制，以及所有旧版 ABI 的布局、
所有权规则和调用约定。可以新增返回 JSON 结果的入口；现有整数结果及调用方拥有/
释放资源的规则保留原有含义。读取方忽略无法识别的可选响应字段，配置编辑器保留
这些字段。未知版本、操作类型或涉及安全的关键请求字段必须被拒绝，绝不能解释为许可。

不得改变现有通话身份语义：`call_id`、`stage_revision`、`dialog_owner` 和发布者
身份各有不同用途。监看者不是通话所有者。应答竞争中的失败方不能终止胜出方的
通话；Ignore 仅在本地生效；访客取消仍是幂等的全局操作，并受现有通话中规则约束。
保留恢复窗口、SOS 清除语义，以及有效的零接收人 SOS 配置。保持 `ios-legacy` 冻结。

通过现有 Core 能力投影增加以下已经测量且已实现的功能项：`operations_v1`、
`admin_sessions_v2`、`web_request_lanes_v1`、`media_publish_v1`、`config_cas_v1`、
`config_conflicts_v1`、`config_import_v1`、`panel_identity_v1`。
每项都是对象 `{version: 1, supported: boolean, limits: object}`。缺失、false 或
未知版本均表示不支持。服务器执行能力约束；客户端不能自行授予功能。
不得仅凭构建标志、SDK 版本或本地摄像头预览成功就声明支持某项能力。

所有受支持的外壳使用同一套 Core 契约：Android modern/API19；现代 iOS/iOS9 arm64/tvOS
共享 Swift；iOS5/iOS9 armv7 共享 Objective-C；Windows x86/x64；以及受支持的 Web
运行环境。物理设备和内存资格验证仍按各目标分别进行。仅修改文档不递增应用版本；
实现和随包资源变更需要递增版本。

## C02：通用封装与字段规则

版本化 JSON 响应保留已有的 `ok` 和 `err`（如原来存在），并增加
`schema_version: 2`。新增的权威字段如下。整数必须是精确、有限的 JSON 整数；
毫秒时长非负，且受对应限制约束。ID 是不透明、区分大小写的字符串，其本身从不
构成持有即授权的凭据。任何字段都不得包含密码、长期令牌、密钥、凭据 URL 或原始
秘密值。未知结果就是未知，不代表物理操作失败或成功。

| 字段 | 类型、边界与默认值 | 含义与生命周期 |
|---|---|---|
| `request_id` | 32 个小写十六进制字符；缺失时由服务器生成 | 关联单次请求尝试；不提供去重或授权 |
| `operation_id` | 由 16 个安全随机字节生成的 32 个小写十六进制字符；prepare 后必填 | 一次用户意图的稳定身份；可在权威节点本地持久查询 |
| `authority_node` | 已有的、通过验证的节点 ID；操作必填 | 该句柄的固定执行节点；绝不能由 HTTP 重试重新选择 |
| `execution_state` | C04 中的枚举；操作结果必填 | 持久状态，不能根据传输状态推断 |
| `error_code` | 协议错误枚举；成功响应中缺省 | 机器可读原因；`err` 仍作为兼容性投影 |
| `retry_mode` | `none`、`same_operation_query`、`same_operation_execute`、`new_prepare`；默认 `none` | 仅为建议；每次重试都要重新授权 |
| `unknown_reason` | `response_lost`、`crash_during_dispatch`、`transport_ambiguous`、`ack_unavailable`；其他情况缺省 | 有界说明，不包含原始传输数据或秘密数据 |
| `config_generation` | 不透明的本地修订字符串，最长 256 字节 | 绑定权威节点快照；不是全局提交编号 |
| `credential_version` | 精确的持久化 LWW 元组 `{hlc, author, seq}`；会话中仅服务器持有 | 与凭据记录原子绑定，不是逐节点计数器 |

`hlc` 和 `author` 使用现有 LWW 编码。新 JSON 中的 `seq` 使用无符号十进制字符串，
以避免 JavaScript 精度丢失；存储仍保留现有整数表示。客户端只比较不透明版本是否
相等，不比较新旧。不得通过版本字段暴露密码哈希。

对于同一权威节点的完整配置快照，`config_generation` 和 `expected_revision` 使用
同一个不透明令牌。令牌包含节点本地的启动/恢复代次和修订身份；即使配置值相同，
重启或恢复也会使旧令牌失效。不保证令牌有序，也不保证跨节点相等。失效后，编辑器
保留草稿并重新获取基准。操作记录存储准备时使用的令牌；执行时不能静默替换它。
复制的冲突父版本使用 LWW 记录身份，而不是这个启动周期本地令牌。

| 情况 | HTTP / 错误 | 重试与 UI 含义 |
|---|---|---|
| 已知查询结果 | 200 | 呈现其执行状态；不暗示物理操作成功 |
| 已接受/正在运行的操作 | 202 | `same_operation_query` |
| 会话缺失/过期 | 401 / `auth_required` | `none`；停止特权重试 |
| 已认证但被禁止 | 403 / `permission_denied` | `none` |
| 过期所有者或已结束通话 | 409 / `stale_owner` 或 `call_ended` | 仅使精确匹配的旧会话失效 |
| 配置已变更或同 ID 参数不同 | 409 / `config_conflict` 或 `idempotency_conflict` | 不得无条件重试 |
| 无效模式/未知关键字段 | 400 / `invalid_request` | `none` |
| 不支持安全协议 | 501 / `unsupported_capability` | 升级/配置；不得采用不安全的回退方案 |
| 请求体/条目容量超限 | 413 / `capacity_exceeded` | 显示限制；不得拆分为对生效配置的部分写入 |
| 操作/认证/工作线程容量已满 | 503 / `capacity_exceeded` | 不额外接纳；显示有界恢复方式 |
| 未知句柄 | 404 / `operation_not_found` | 查询不能重建句柄；execute 绝不执行 prepare |
| 缺失配置基准 | 400 / `revision_required` | 重新加载/比较，同时保留草稿 |
| 固定权威节点缺失或不可达 | 503 / `authority_unavailable` | 不得替换执行节点 |
| 已证明在排队时过期 | 503 / `not_started` | 重试策略取决于是否仍有有效的已准备句柄 |
| 运行中请求丢失响应 | 202，或在无结果可用时返回 503 / `outcome_unknown` | 查询原操作；绝不自动创建替代操作 |

浏览器超时、网络失败、中止和解析失败都是本地错误。对于写操作，除非服务器返回
可验证的 `not_started` 结果，否则这些错误意味着结果未知。脱敏要求同样适用于错误、
诊断信息和日志。

通过 Cookie 认证的修改请求，必须在请求头中携带与会话绑定的随机 CSRF 令牌，并
精确匹配已配置的 Origin 允许列表；对新增 Web 修改路由，缺失、null 或不可信的
Origin 均必须拒绝。经过认证的非浏览器原生/mesh 请求使用各自明确的主体，不能
通过省略 Origin 绕过授权。仅靠 SameSite 不够。只有部署配置明确指定时才信任代理；
任意 X-Forwarded 请求头不能建立 Origin、权威节点或身份。不得使用带凭据的通配符
CORS，也不得在 URL、事件或诊断包中包含 CSRF/令牌值。

## C03：HTTP 调度

调度状态为 `QUEUED -> RUNNING -> COMPLETED` 或 `QUEUED -> EXPIRED`。
截止时间验证和状态迁移共享同一把锁或同一个原子决策。只有赢得
`QUEUED -> EXPIRED` 迁移的一方才能证明 `not_started`。已过期工作绝不能再运行。
HTTP 超时不能通用地撤销已经运行的工作。

保留现有 5000 ms 等待上限。请求和完成上下文必须有明确所有者；绝不保留 HTTP
栈引用，也不得在处理函数退出后继续使用连接。完成、关闭和过期只能结算一次。
转发网络工作绝不能在 Core 循环上同步等待。调度状态与持久操作状态分离；查询过期
不会取消其操作。

## C04：准备、执行、查询与物理证据

预留版本化路由 `POST /api/operations/prepare`、
`POST /api/operations/<operation_id>/execute` 和
`GET /api/operations/<operation_id>`。当前构建中尚不存在这些路由。
新增原生 JSON ABI 适配器必须委托给同一组 Core 函数，并通过既有 ABI 所有权约定
释放结果。

Prepare 接受 `{schema_version:2, action, door?, parameters}`。操作类型为
`door_open`、`sos_start` 和 `sos_clear`；未知操作被拒绝。只有 `door_open` 要求
`door`，它使用现有通过验证的门 ID，不能是任意地址。SOS 仍然是集群全局操作，
省略 `door`；SOS 请求携带门时必须拒绝，不能静默缩小其范围。版本 1 对这三种
操作使用空参数对象。Source/via、开锁命令和 SOS 投影从经过认证的 Core 状态及
配置中推导，不能由调用方参数指定。未来的参数模式需要修订 ADR；下述容量不代表
允许传入任意参数。参数是经过验证的对象，UTF-8 编码后最多 4096 字节，
最大深度 8。Core 解析操作、权限、当前配置和确切的权威节点；规范化的有类型参数
冻结在记录中。指纹是该规范表示的 SHA-256；调用方提供的指纹绝不能替代验证。
未知关键参数必须被拒绝。

Prepare 返回句柄和 `prepared_remaining_ms`，最长 30000 ms。它不产生物理效果，
不增加额外确认等待，也不在应用启动时预先请求。Prepare 响应丢失最多只能留下一个
有界、会过期的记录。Execute 携带同一操作及不可变参数（或引用已经冻结的参数，
不替换它们）。参数相同的重复执行返回现有状态；参数不同则返回冲突。
请求体要么仅包含 `{schema_version:2}`，要么包含完整的原始 prepare 请求体；部分
替换及无法识别的字段返回 `invalid_request`。
Execute 不能创建或恢复未知、已移除或已过期的 ID。

新增持久化权威绑定为 `doors.<id>.operations.authority_node`，通过同一套经过验证
的配置服务管理。它覆盖开门操作。全局 SOS 使用独立的
`cluster.operations.sos_authority_node` 绑定，并保留现有全局紧急事件及呈现/接收人
规则，包括未配置任何门的部署。权威节点缺失或有歧义时，以
`authority_unavailable` 禁用新协议；不隐式采用 MQTT leader 或故障切换执行节点。
集群/全局 SOS 必须解析该全局权威节点，不能选择一扇门。在新能力投入使用前，
现有旧版 SOS 仍按其已记录的较弱契约保持可用。变更权威节点要求旧权威节点停止
接纳和执行工作，并核对解决未完成操作。
不支持网络分区期间的故障切换；不得仅因权威节点不可达就更换它。

每条记录绑定经过认证的主体、门或全局范围、操作、权威节点、参数/指纹、凭据/授权版本、配置
代次、启动代次、创建/接受时间及有限结果。主体由服务器根据会话/原生注册/经过认证
的 mesh 跳点推导；请求 JSON 不能自行选择主体。Prepare、execute 和 query 都要求
当前有效的门/操作权限；全局 SOS 则要求现有的全局 SOS 启动/清除权限。门授权不能
隐含授予全局 SOS 清除权限。查询允许创建操作的主体及有权限的管理员执行；仅知道 ID
不授予任何权限。Execute 重新验证权限和目标配置。配置或授权变更使未开始的记录
被拒绝；绝不能把它重新指向另一把锁。

状态为 `prepared -> accepted -> dispatching -> dispatched -> actuator_ack`。
尚未开始的终态为 `rejected_not_started`、`expired_not_started`、
`failed_before_dispatch`。派发结果不明确时转为 `unknown_after_dispatch`。
派发执行权的取得及其必需的本地副作用意图，必须在外部 I/O 前通过一次 Store
事务持久化。每个 ID 只允许取得一次派发执行权。重启使 prepared 记录失效。
对于 accepted 记录，若有持久证据证明尚未取得派发执行权，则确定为
`failed_before_dispatch`；dispatching 或状态不确定的记录转为 unknown，绝不自动
重发。在已经证明未开始的失败之后，用户可以明确准备一个新意图。绝不复用或延长
旧启动周期的单调时钟截止时间。

`dispatched` 表示适配器接受了发送，不表示门已经打开。经过认证的执行器 ACK 必须
匹配操作、权威节点和已配置执行器，并作为 `actuator_ack` 单独记录。延迟但有效的
ACK 可以在不重发的情况下确定未知结果。传感器观测是独立的
`{state, observed_at_ms, operation_id?}` 证据；没有关联的传感器变化不能证明因果
关系。没有感知操作 ID 的执行器去重机制时，MQTT 重投使端到端恰好一次保证无法
成立。绝不能宣称提供这种保证。

限制：每个权威节点最多 128 条 prepared 记录，以及 2048 条 accepted/active/
未解决 unknown 记录。终态查询结果至少保留 24 小时；绝不静默淘汰未解决的 unknown。
每个结果最多 4096 字节；每页查询最多 32 行。所有状态合计最多预留 4096 行和
48 MiB 的逻辑记录载荷，为每条接纳的记录预留 12 KiB，分别容纳最多各 4 KiB 的
参数、结果和元数据。在任一预留上限将被超过前，拒绝新的 prepare。终态迁移使用
该记录现有的预留空间，不占用新槽位。只回收进入终态超过 24 小时的记录；不得为
接纳新流量而淘汰更年轻的已完成/已过期记录。实际 SQLite/WAL 开销、检查点和
空间不足行为需要 T05/目标测试；逻辑字节上限不代表数据库文件总大小的保证。
记录行存储在磁盘上；不得把整个台账
加载到内存。容量达到上限时明确拒绝新的 prepare，同时保留现有查询和控制路径。
旧的单次 ABI 端点保留其原有尽力而为语义，并且只有在完成实现后，才可安全地适配为
一次内部 prepare/execute。它们无法对彼此独立的旧版调用去重，也不能自动重试结果
不确定的写入。新增受支持 UI 在 T36 中迁移；旧版入口在迁移前仍需明确列为保证较弱
的入口。

SOS 准备必须始终能立即发起。准备失败或无法到达权威节点时，显示未发送/未知状态
和可用的替代求助方式；不得编造已送达状态、静默清除活跃 SOS，或使用新 ID 重试。

## C05：管理员与面板会话

管理员会话必须在与凭据相同的串行化快照中，绑定当前 `admin.password_hash` 的
完整 LWW 记录版本。每次请求都要对照本地已知的最新版本检查。本地变更、远程同步
和配置恢复都必须触发失效处理。按交互活动计算的空闲过期时间为 30 分钟；绝对
生命周期为 8 小时；容量为 64。轮询/心跳不刷新交互时间。先清理过期会话，再淘汰
最近交互时间最早/最旧的会话，但排除刚签发的令牌。令牌保存在内存中；重启使其
全部失效。绝不能因台账持久化而意外持久化新会话令牌。
当前分离的元数据/配置事务尚不能使凭据更新具备原子性；T08 必须让凭据及其记录
版本共享一个持久提交边界，并在声明支持该能力前测试回滚/恢复。

分区中的节点可以继续使用其本地已知凭据。一旦获知记录变更，就立即拒绝旧会话。
仅靠令牌过期，不能阻止用户使用孤立节点上的旧密码反复登录。应报告撤销仍待传播，
不得承诺即时全局撤销。严格离线撤销需要另行批准的在线权威服务，并明确接受无法
离线管理这一代价。

面板身份、短期 Web 会话、通话所有权和媒体租约彼此不同。T31 分配随机 `panel_id`，
绑定明确的门/操作授权，并使用已有面板凭据代次/引用使会话失效。面板 ID 最多
64 个 ASCII 字符，绝不从 IP 或 UA 推导。旧版共享凭据仍标为 `legacy_shared`；
不得宣称支持逐设备撤销。可独立使用的 SIP 身份需要真实 PBX 配置；未配置时报告
`provisioning_required`，不能虚构分机号。

新增的身份绑定面板 Web 会话使用保存在内存中的随机 128 位令牌，交互空闲过期时间
为 30 分钟，绝对过期时间为 8 小时，容量为 128。只有明确的用户交互才刷新空闲
时间；后台轮询不刷新。按管理员会话相同的规则处理过期/淘汰，保护新签发的令牌。
重启、身份/授权撤销及已获知的凭据版本变更使会话失效。续期要求经过认证的面板
身份引导（平台安全存储/本地 Core 或用户登录）；旧 Cookie 过期后，绝不能仅凭该
Cookie 续期。不得在浏览器 URL 中放置长期身份凭据。令牌/CSRF 值是不透明秘密；
诊断和协议示例输出必须将其脱敏。在 T31 迁移调用方前，现有旧版共享会话仍明确
保留较弱保证；缺失身份不能成为享有特权的默认情况。

## C06：独立请求与 Core 时间

| 请求通道 | 周期 | 截止时长 | 在途上限 |
|---|---:|---:|---:|
| state | 1000 ms | 3000 ms | 1 |
| call-info | 5000 ms | 4000 ms | 1 |
| locale | 仅在语言变更时 | 4000 ms | 1 |
| SOS write | 用户意图 | 4000 ms | 每个操作 1 个 |
| heartbeat | 2000 ms | 1500 ms | 1 |

每条通道拥有自己的计时器、代次和仅结算一次的取消机制。超时的旧回调不能修改新
通道/通话。旧浏览器使用现有兼容请求层，并确保实际配置超时。保留服务器现有的
10000 ms 所有者租约。网络/5xx 重试只允许在剩余租约内使用 500/1000/2000 ms 退避。
明确的所有者过期、通话结束或授权撤销，只使对应旧会话失效。不得无限延长租约。

复用已经引入的 `active_calls`、`server_now_ms`、`remaining_ms` 和
`expires_at_ms` 快照；不要再创建第二套倒计时 API。墙上时钟字段是经 Core 校正
的 Unix 毫秒时间，绝不是客户端操作系统墙上时钟。在权威心跳结果中增加
`lease_remaining_ms`（0..10000），并绑定通话/修订/所有者。以请求的单调时钟开始
时间加上服务器剩余时长，保守估计过期时间；响应到达绝不意味着获得一份全新的
完整租约。客户端/权威节点重启或返回前台后，重新获取快照。不承诺后台浏览器
无限期持有所有权。过期状态不会自动清除活跃 SOS。

## C07：媒体授权与传输

发布授权绑定经过认证的主体、门、`call_id`、`stage_revision`、`dialog_owner`、
`media_generation` 和过期时间。增加随机 128 位 `media_generation`，编码为 32 个
小写十六进制字符，以及该代次内
从 1 开始、最大为 9223372036854775807（19 位）、严格递增的十进制字符串
`frame_sequence`。不得有前导零、正负号或指数，也不得回绕或复用；需要时更新
代次。发布元数据是瞬态数据，绝不是 CRDT 事件。Core 从经过认证的状态中推导主体
和所有者。身份字段缺失则拒绝上传。结束/撤销立即使该代次及其缓存帧失效；在最终
写入帧总线前再次验证。
服务器推导出的发布者是经过认证的面板身份或原生节点/通话绑定，不能由请求选择
面板 ID。授权保存在内存中，在 10000 ms 内过期，并且绝不超出当前所有者租约或
Web 会话的生命周期。返回整数 `publish_remaining_ms`，范围为 0..10000。
续期重新授权完全相同的元组，并返回新代次；旧代次不能恢复。权威节点重启、通话/
修订/所有者变化或显式撤销均清除授权和帧缓存。迟到帧绝不延长租约。客户端与 C06
相同，从请求的单调时钟开始时间估计该时长。

浏览器使用同源相对 URL。Core 从可信配置解析对端；禁止任意上传/代理 URL、通过
重定向改换目标、转发浏览器 Cookie，以及使用长期凭据。当前采用 PSK 认证和加密的
SecureChannel 是可复用的原语，但尚不是安全的媒体传输实现：其加密和回调目前在
Core Runloop 上运行，且待处理队列没有上限。
现有 SNAP 限制为 300 KiB/5000 ms，并丢弃超大 JPEG；BLOB 限制为 3 MiB，采用
256 KiB 分块/10000 ms。它们不是新增的 1 MiB/3000 ms 媒体协议，也不是现成的
4 MiB 导入传输。保留这些旧限制，并为新通道引入版本，而不是静默提高共享限制。

T16 必须使用该现有的认证加密原语实现独立、有界的媒体执行上下文，不能使用
CRDT/事件通道。控制循环检查签发与代次绑定的权威快照；工作线程拥有网络/加密
缓冲区；最终 Core 循环检查拒绝过期快照。可信对端连接认证每一跳，并且只有依据
经过认证的源节点已验证的授权，才能映射被委托主体。绝不接受浏览器自行提供的
身份作为委托。在该绑定、工作线程所有权、关闭过程和队列边界通过复核/测试前，
跨节点 `media_publish_v1` 保持不支持（该传输通道为 `DESIGN_BLOCKED`）。
不存在裸 HTTP 或公共上传回退路径。

编码帧最大 1 MiB；解码像素数最多 307200；任一维度最大 1024。在分配/解码前
验证长度和 JPEG 尺寸，并严格限制请求读取器。当前 8 MiB HTTP/TCP 阈值尚不能
提供这种拒绝行为。每个发布者：一帧在途，加一帧最新待处理帧，以新帧替换旧待处理
数据。每个节点：最多 8 项授权、一个媒体工作线程、总量 2 MiB 的编码帧队列，以及
每个发布者每秒 2 帧。接纳同时受全局和逐发布者限制；队列满时丢弃已被替代的帧
或拒绝，绝不继续增长。网络截止时长为 3000 ms。媒体缓冲区与控制/SOS 容量分离。
目标可以声明更低的实测限制；不支持的目标不得声明支持发布。

UI 状态为 `local_capture_ready`、`sending`、`remote_core_accepted`、
`interrupted`。任何一种都不意味着远端屏幕已经显示该帧。未来的渲染 ACK 必须
匹配同一代次/序号，才能作出更强的声明。本地预览不是端到端媒体证据。

## C08：配置 CAS、冲突与导入

在通用配置修改服务中增加 `expected_revision`，即最长 256 字节的不透明本地
修订值。快照、比较、合并、验证和提交在一次串行化 Store 事务中完成，只有成功
后才发布内存状态和事件。新增端点缺少修订值时返回 `revision_required`；现有明确
标为旧版的单次写入端点，在迁移前保留其已记录的较弱行为。不得默认使用当前修订值。

三方合并使用 base/mine/current，并保留未知字段。缺失、null 和删除彼此不同。
没有稳定身份的数组按整个数组判定冲突。本地 CAS 不是集群共识。复用现有 LWW
传输，并为每次本地编辑原子地增加持久化、经过认证的冲突意图记录：随机 128 位
`change_id`（编码为 32 个小写十六进制字符）、父版本、作者节点、变更字段路径和
非秘密候选值。单条记录上限为 64 KiB、256 个变更字段，且每个变更字段最多
2 个父 LWW 记录版本。父版本使用 C02 的 `{hlc, author, seq}` 编码，并在重启后
仍然保留；缺少父版本表示该字段在观测到的基准中不存在，不表示允许覆盖该字段。
秘密字段仅保留引用/版本/冲突元数据，
绝不保留明文候选值。持久保留未解决冲突；容量达到上限时拒绝新的相关写入，而不是
静默丢失可恢复的意图。T28 必须在声明支持 `config_conflicts_v1` 前定义有界存储/
索引实现；当前仅保留胜出值的 LWW 不足以满足要求。重连可以选择生效的 LWW 值，
同时保留可见的未解决意图。只有管理员明确解决冲突，才生成同时引用两个父版本的
新变更；不得在每个对端持续自动写入合并值。

普通批量输入保持 256 项。为导入预留独立的暂存、预检和提交操作；不得向旧批量
接口传入 4096 项，也不得逐块写入生效配置。导入限制为：上传字节数 4 MiB、展开
后的叶级修改 4096 项、最大嵌套深度 16、每个经过认证的管理员主体最多一个活跃
暂存，以及 10 分钟 TTL。令牌为 128 个随机位，绑定主体、上传摘要、权威节点启动
代次、基准修订值和过期时间，其自身绝不是持有即授权的凭据。重启使暂存失效；
清理删除其拥有的临时数据。因速率/容量而拒绝时，必须保留当前生效配置和用户的
原始导入文件。

预检报告完整差异、模式问题、缺失的秘密引用和资源。提交重新授权，比较同一基准
修订值，复用通用验证器，然后在一个节点上原子提交整个快照。崩溃恢复后只能是旧
状态或新状态，不能是导入一半的状态。这不代表集群范围的同步切换。缺失秘密通过
平台安全存储恢复；普通 JSON 导出不是完整的灾难恢复备份。不得临时自创加密备份
格式，也不得包含明文秘密。

## C09：限制、资格验证与归属

上述数值限制是协议接纳上限，不是在旧硬件上的实测声明。T01 验证了当前读取器的
实际限制、基线行为和可用工具链，没有验证尚未实现的台账/导入器的内存占用。
各负责实现的任务必须展示有界分配/存储及达到上限时的行为；目标任务 T40-T48 必须
验证各自适用运行环境的资格。目标实测限制更低时，应明确声明并在服务器执行。
如果某个必需目标无法满足契约，记录 BLOCKED_ENV 或 DESIGN_BLOCKED 及其具体
局部原因；不得提高最低操作系统版本、移除安全检查或标记整个计划完成。上述跨节点
媒体和冲突保留实现门槛仍待满足；T02 复核不能替代它们。
