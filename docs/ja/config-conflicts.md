# 設定競合の保持

同一ノードの同時編集は revision 比較で保護します。切断中の複数ノードは既存の LWW 複製を維持するため、再接続で有効な設定が変わる場合があります。更新済みの設定書き込み経路は編集意図を保存し、管理画面で未解決の候補を表示します。自動マージや勝者の繰り返し書き込みは行いません。

## 記録と原子性

通常の設定変更と不変の `_config_changes.<change_id>.<sha256>` 記録を同じ SQLite トランザクションに保存します。失敗時はどちらも公開しません。SHA-256 は記録内容を固定し、認証と機密性は既存の Mesh SecureChannel が担います。記録は通常の設定、エクスポート、ルール評価、実行イベントから除外します。不明なフィールド、重複、循環、作者・ダイジェスト・親バージョンの不一致はバッチ全体を拒否し、永続化済み複製位置を進めません。

schema 1 はランダムな 128-bit change_id、author_node、entity、base_entity_version、parents、typed ops、candidate_exists、candidate、requires_reentry を含みます。各操作は set/delete、key と最大 2 個の base_versions を持ちます。最も近い既存の祖先と同一キーの LWW 記録を `{key,hlc,author,seq,deleted}` で表し、seq は十進文字列です。親がない場合は記録が未存在です。entity の基準ダイジェストは変更前の全 LWW 記録識別子を含みます。1 記録は最大 256 操作、64 KiB です。

entity は先頭の設定セクション単位ですが、devices は `devices.<id>` ごとです。devices 全体の書き込みと削除は拒否します。別分岐の異なるフィールドも保守的に競合扱いします。公開された単一・batch・CAS・import・公告 API は同じ記録境界を使います。起動時・実行時の内部保守と認証サービスは既存の別契約を維持します。旧ノード自身の編集意図は保存されないため、混在環境で完全な競合保護を主張できません。

## 表示と解決

`/api/config/snapshot` と既存の native ABI は edit_conflicts と edit_journal を追加します。競合には entity、現在の全 head、有効値、分岐記録を含みます。candidate_exists=false は削除、true と null は実際の null 値です。

未解決の entity の通常変更は unresolved_config_conflict になります。管理者の既存認証・CSRF・Origin 付き条件コミットに `resolves:{"entity":["全現在head"]}` と同じ entity の set/delete を指定します。解決用 set は省略フィールドと古い子記録を削除する完全置換で、通常の設定検証も必要です。同じトランザクションで revision と head 全集合を比較し、古い選択を拒否します。新しい記録が全候補を親として参照し、再同期だけでは記録を増やしません。

保護値は requires_reentry マーカーに置換します。有効な secret: 参照は保持し、平文の認証情報や認証情報付き URL を候補へ保存しません。不完全な候補は直接適用できず、既存の安全な保存先と参照の仕組みで再入力します。競合解決は欠けた端末内シークレットを復元しません。

## 保持上限

ローカルは計 512 記録、entity ごと 64 記録、512 KiB。リモート集合用余裕は計 1024、entity ごと 128、1 MiB です。上限時は config_history_capacity_exceeded を返し、編集を公開しません。リモートの不正・超過バッチは直前の状態を維持し、runtime.config_store にエラーを表示します。

通常のイベント保持や tombstone 清掃では編集記録を削除しません。初版は解決済み祖先も保持し、全員の保持を証明する圧縮処理はありません。このため追加編集や解決が容量で停止する場合があります。未解決候補を消して受付を続けません。上限拡張や安全なアーカイブ・圧縮には別途資源・復旧検証が必要です。通常の設定エクスポートは履歴と端末内シークレットを含まず、完全な災害復旧バックアップではありません。
