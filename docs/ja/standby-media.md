# 待機メディアと初回フレームの検証

室内 Core は直接接続された玄関端末に対し、最大四本の認証済みメディア接続を保持します。玄関端末ごとの待機所有者は最大八台で、HTTP メディア接続数の上限にも含まれます。制御には既存の認証済み mesh 接続を使い、映像は証明書を固定した独立の HTTPS 応答で送ります。

`GET /media-standby.mp4` は有効なピア MAC と、`X-Doorbell-Channel` の 32 文字の接続識別子を要求します。応答形式は `application/x-doorbell-standby-v1` です。待機中は毎秒 12 バイトの `dbrt` ボックスを送り、標準 MP4 ヘッダーの後にビッグエンディアンの回転角度を格納します。待機中は VideoTrack の購読がなく、H.264 エンコードと受信側デコードを行いません。起動時だけ期限付きのローカル購読でエンコーダーを準備します。形式が変わるたびに初期化情報を一度だけ待機接続で送り、kiosk は映像をデコードせずデコーダーを準備して保持できます。実行状態の重複更新を除き、短時間の更新をまとめます。呼び出しイベントと開始コマンドは即座に送ります。

mesh コマンド `standby_video_v1` は開始トークンを要求者と接続に結び付けます。ゼロは停止を示します。動作中は五秒ごとに更新し、十五秒間更新されなければ期限切れになります。開始時はトークンと送信元のシステム時刻ミリ秒値を含む 24 バイトの `dbeg` ボックス、初期化データ、fMP4 断片を送ります。新しい IDR を要求し、開始前のキャッシュ IDR は渡しません。受信側も古いトークンを破棄します。購読のキューは 4 MiB と 128 ボックスが上限で、超過時はフレーム依存を壊さず購読を終了します。

呼び出し通知は UI に通知する前に購読を予約します。予約は五秒後、または呼び出しが終了すると失効します。二人目の同時視聴者は従来経路を使います。メンバー削除、鍵変更、接続先や証明書の変更、ハートビート停止、終了時には接続を無効化します。旧端末には従来の HTTPS 経路を残し、失敗時の接続試行間隔は最低十五秒です。

`media-startup` ログは DNS、TCP、TLS、要求送信、応答ヘッダー、最初の応答データ、待機接続の開始待ちを分けて記録します。kiosk は呼び出し受理、要求、デコーダー設定、IDR 受信、UIKit 提出、最初の撮影時刻を記録します。`press_local_wall_ms` は補正後の呼び出し時刻を受信端末の未補正システム時刻に変換します。`capture_cutoff_ms` と撮影時刻は送信端末の未補正時刻です。補正時刻と未補正時刻を混在させてはいけません。 メディアログは上限付きキューで非同期に書き込みます。ログの到着時刻ではなく、埋め込まれたイベント時刻を使います。

認証済みループバック UI は Core が予約した購読を状態ループへの再投入なしで取得できます。他の要求は従来どおりメディア権限を確認します。
