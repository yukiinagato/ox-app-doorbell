## Reviewed decisions

- **Authenticated bytes and parser.** A bounded flat envelope requires all eight exact fields once, with lowercase fixed-length hexadecimal IDs/digest/signature and delimiter-free identifiers. The independent test signer follows the documented domain-separated byte string, including final newlines. This avoids ambiguous JSON signing. Existing Monocypher performs Ed25519 verification; no custom cryptographic algorithm was added.
- **Weak keys.** The wrapper requires canonical y encoding below the field prime and rejects the five low-order y coordinates with either sign. I compared these constants against the [official libsodium 1.0.18 checks](https://github.com/jedisct1/libsodium/blob/1.0.18/src/libsodium/crypto_core/ed25519/ref10/ed25519_ref10.c#L966). The bundled Monocypher code itself validates curve decoding and signature scalar range, while allowing noncanonical point encodings internally; the wrapper's commissioned-key check is therefore material. The production test demonstrates the bundled verifier's degenerate identity-key acceptance and the wrapper's rejection, not merely a source-string assertion.
- **Source/target authority and revocation.** MQTT delivery alone is insufficient. The current fixed door authority, ACK protocol, actuator ID and commissioned public key must validate first. The durable record must then show dispatch acquisition and match the exact operation, authority, door, actuator, frozen ACK key, current/frozen command and broker/topic binding digest. Removing/rotating the key, reassigning the authority or changing the target cannot authorize an old ACK through a new binding. The internal ledger read follows signature validation and does not replace ordinary HTTP query permissions.
- **Late results.** Updates use the immutable operation ID and authority, never a current-door pointer. Two IDs, a front-to-rear switch, duplicates and out-of-order ACKs change only their own rows. A prepared record cannot be upgraded by an unsolicited authentic ACK. A valid late ACK can reconcile an unknown original record after restart without another command. Ordinary sensor-shaped/unsigned/retained messages cannot create acknowledgement.
- **Durable once-only acquisition and reference deduplication.** The actual Store transaction still owns dispatch acquisition. Feedback never re-enters the command adapter. The reference executor commits pending before its simulated effect, keeps completed results durably, rejects same-ID changed digests, and leaves pending-after-crash unresolved without redoing the effect or issuing a success ACK. This remains a reference contract, not deployed actuator firmware or an exactly-once physical guarantee.
- **Timeout, capacity and shutdown.** Configured feedback has a four-second monotonic timer; no-feedback sends remain explicitly unconfirmed. Disconnects mark bounded watches unknown and do not replay on reconnect. The watch map is checked against the existing 2048 active-operation ceiling, and a disconnect turn writes at most 32 records. Timers/sweeps use the Node lifetime token, shutdown cancels them, and already acknowledged terminal rows cannot be regressed by a later unknown transition.
- **Honest result language.** `actuator_ack` reports authenticated command processing and still returns `physical_state:unconfirmed`. The source/docs do not equate a sent packet, a broker connection, an uncorrelated sensor observation or a test executor with a physically opened door.
