# T08 管理员会话执行报告

状态：VERIFIED_IN_SCOPE（production_test），独立复核通过。来源为 source-final-r4.json；冻结源位于 build/remediation-continuation-20260922/t08-candidate-r4。HEAD仍为 b26e0d346df99f2879915241b6e98d8ef1aa0707，工作树有保留的并行修改。

会话绑定已持久化管理员 CRDT 记录的内部版本；本地改密、远端合并及配置恢复均经配置重建同步发布新版本。凭据 CRDT 与本地密码元数据在同一 SQLite 事务提交，失败保留旧凭据与会话。HTTP 实际执行前再次鉴权，排队期间撤销的会话不能写入。

实际生产会话表采用单调时间，30 分钟交互空闲、8 小时绝对期限、64 个记录上限；插入新令牌之前稳定淘汰最旧记录。轮询和会话令牌查询不续期；已鉴权的可信用户交互最多每分钟续一次空闲期限。新增写接口要求会话绑定随机 CSRF 头及精确可信 Origin，缺失/null/外域/错误或其他会话的令牌均被拒绝；DNS/代理来源需明确配置，不信任 Host 或转发头。英文及日中配置文档已同步。

最终实际测试：23/23、736 个断言通过；生产管理页交互回归通过。T08-01/05 使用真实两个 Node、HTTP 和 InMemNet，分区期间 B 保留旧凭据行为明确可见，合并后旧会话 401 且新密码可登录。T08-02 直接执行生产会话表，64 个旧令牌后插入低字典序新令牌保持有效。T08-03/04 真实 HTTP 配合 SimClock 推进单调时间并回拨墙钟；后台读取不能续期，绝对到期、倒退单调时间与边界值另由生产会话表测试覆盖。附加测试实际注入 SQLite 配置/metadata 写失败，验证全回滚、成功后撤销和关闭重开一致；排队鉴权撤销后业务处理器未执行。见 evidence/acceptance.json、final-core-r4.log、final-web-r4.log、review.json。

历史失败保留：最初两项业务 red 证明旧版没有空闲到期/同步撤销；排队撤销 red 证明旧 handler 会继续执行。第一次最终构建遇到并行 Store 声明/实现交错，随后增量产物出现 Store 布局不一致导致 mutex 错误；整套 clean r3 重新编译后23/23、693断言通过。r4 将全部输入复制到冻结目录后完整构建，加上独审要求的 CSRF/Origin 用例，最终736断言通过。不把中间构建失败当作业务 red，所有记录保留。

本卡不承诺分区中立即撤销远端会话，也不阻止尚未同步节点使用旧密码重新登录。主机产物使用 SIP stub，仅验证生产 HTTP/会话/存储路径，不是发布或真机认证。受影响应用版本由主任务整批递增；没有真实门锁、SOS 或发布操作。
